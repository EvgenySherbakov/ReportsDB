# Правила работы над проектом

Этот файл читает AI-агент перед началом работы. Полное ТЗ — [`docs/TZ.md`](docs/TZ.md).

---

## Главное правило общения с заказчиком

**После каждого изменения, попавшего в git, обязательно писать в ответе два
блока — даже если кажется, что это очевидно или ничего не поменялось:**

### 1. Что обновить локально

- нужен ли `git pull` (нужен всегда, когда что-то запушено);
- **нужно ли перезагружать данные** — обязательно, если менялись
  `sql/01_schema.sql`, `sql/02_views.sql` или структура загрузки;
- нужно ли переустанавливать зависимости — только если менялся `pyproject.toml`;
- что делать **не** нужно (не клонировать заново, не удалять файлы вручную).

### 2. Как запустить

Готовые команды, которые можно скопировать. Заказчик работает на **Windows**,
проект лежит в `C:\rep_dev\ReportsDB\ReportsDB`, поэтому:

- команды давать для Windows (`scripts\run.bat`, обратные слэши), при
  необходимости добавлять вариант для macOS/Linux;
- начинать с остановки приложения (`Ctrl+C`), если оно запущено;
- заканчивать тем, что открыть в браузере и что нажать.

Формат — короткий пронумерованный список шагов, без объяснений, зачем каждый
шаг нужен. Пояснения — отдельно, ниже.

Заранее предупреждать о вероятных сбоях (`git pull` с локальными правками,
занятый порт) и давать готовое решение.

## Правила по данным

**Рабочие данные не покидают машину заказчика.** Подробно — раздел 3.1.1 ТЗ.

- никогда не коммитить содержимое `data/` и `dist/`;
- не вставлять реальные имена отчётов, таблиц и схем в код, тесты,
  документацию, сообщения коммитов и описания PR;
- для примеров использовать только синтетику из `python -m reportsdb sample`;
- после `git add -A` проверять: `git ls-files | grep -Ei "\.(duckdb|xlsx|xls|csv)$"`
  должно быть пусто.

## Правила по коду

**При изменении `sql/01_schema.sql` или `sql/02_views.sql`** обязательно:

1. поднять `SCHEMA_VERSION` в `src/reportsdb/config.py`;
2. обновить слепок в тесте `test_schema_version_matches_view_set`;
3. в ответе заказчику написать, что **нужно перезагрузить данные**.

Без этого у заказчика останется несовместимая база, а приложение не сможет
предупредить об этом понятным текстом.

**Имена колонок Excel живут только в `config/mapping.yml`.** В коде ETL их быть
не должно — раздел 3.3 ТЗ.

**Страницы приложения лежат в `app/views/`, меню собирается в `app/Home.py`
через `st.navigation`.** Папка `pages/` не используется: она не поддерживает
вложенные разделы. `set_page_config` вызывается один раз — в `Home.py`.

**Каждое загруженное поле обязано быть видно в аналитике.** За этим следит
`test_every_loaded_field_is_visible_in_analytics`: добавили колонку в загрузку —
доведите её до витрины.

## Проверка перед коммитом

```bash
PYTHONPATH=src python3 -m pytest tests/ -q
```

Интерфейс проверять в браузере, а не «на глаз по коду»: страницы Streamlit и
собранный `dist/reportsdb.html` открывать через Playwright и убеждаться, что
нет трассировок и `nan` в показателях.

**Открыть страницу недостаточно — нажимать тоже.** Карточка отчёта рисуется
только после щелчка по строке, и именно там жил сбой, который обход страниц не
заметил.

**Строки, которые можно выбирать, — это кнопки, а не `st.dataframe`.**
`st.dataframe` выделяет строку только флажком в левой колонке; щелчка по
строке он не видит, и обойти это внутри виджета нельзя. Для выбора
использовать `row_picker()` из `app/_shared.py`. В проверках Playwright такую
строку надо искать среди `button` с « · » в подписи и обязательно отсеивать
невидимые: неактивная вкладка остаётся в DOM, и `bounding_box()` у неё `None`.

**Пустое значение проверять только через `pd.isna`.** Приём «значение не равно
самому себе» ловит `float('nan')`, но целочисленная колонка с NULL приходит из
DuckDB как nullable `Int32`: там пусто — это `pd.NA`, а `pd.NA != pd.NA` даёт
`pd.NA`, и страница падает с «boolean value of NA is ambiguous». В показателях
использовать `num()` и `is_blank()` из `app/_shared.py`.

## Правила по диаграммам

**Цвета в диаграммах не подбирать на глаз — проверять скриптом.** Палитра в
`app/_shared.py` проверена `validate_palette.js` из навыка `dataviz` под тёмный
фон `#0f1419`. Меняете цвет или добавляете ряд — прогоните проверку заново.

**Круговая диаграмма — максимум три доли**, и это потолок палитры, а не вкус:
в круге сравниваются все доли между собой, а четвёртый цвет не проходит проверку
на различимость даже при полном цветовосприятии. Рисовать только через `donut()`
из `app/_shared.py` — он сам откажется от четвёртой доли. Классов больше —
сворачивайте хвост в «Прочие» или берите столбики одним цветом.

**Две шкалы в одних координатах запрещены.** Диаграмма Парето со столбцами и
кривой на разных осях читается неверно; вместо неё — кривая накопления отдельно,
величины в таблице (пример — страница ABC-анализа).

**`backgroundColor` в `.streamlit/config.toml` и `SURFACE` в `app/_shared.py`
обязаны совпадать** — этим цветом рисуются зазоры между сегментами диаграмм,
расхождение видно как кайма вокруг долей.

## Правила по документации

**Документация двуязычная, и обе версии правятся одним коммитом.** Русский
файл — оригинал, английский лежит рядом с суффиксом `.en`:

| Оригинал | Перевод |
| --- | --- |
| `README.md` | `README.en.md` |
| `docs/RUNBOOK.md` | `docs/RUNBOOK.en.md` |
| `docs/ARCHITECTURE.md` | `docs/ARCHITECTURE.en.md` |
| `docs/TZ.md` | `docs/TZ.en.md` |

`CLAUDE.md` остаётся только по-русски: это инструкция агента, а не
пользовательская документация.

Правила:

- **скелет заголовков обязан совпадать** — за этим следит
  `test_translations_keep_the_same_structure`. Добавили раздел в русскую
  версию — добавьте и в английскую, иначе тест упадёт;
- **запись в журнал решений идёт в обе версии** (`test_decision_journal_is_kept_in_both_languages`);
- **имена колонок Excel не переводятся.** `Наименование отчета`, `SEGMENT_TYPE`,
  `ТС`, `Завод` — это строки из файла заказчика, в английском тексте они
  остаются как есть; перевод даётся рядом в скобках, если нужен;
- переключатель языка — первой строкой документа, после заголовка.

Обновлять журнал решений в разделе 15 ТЗ после каждого содержательного
изменения.
