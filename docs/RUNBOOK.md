# Инструкция по запуску

**Русский** · [English](RUNBOOK.en.md)

Три способа. Выберите один — они не зависят друг от друга.

| Способ | Что нужно | Кому подойдёт |
| --- | --- | --- |
| [А. Docker](#вариант-а--docker) | Docker Desktop | Большинству: ставится один раз, дальше одна команда |
| [Б. Python](#вариант-б--python) | Python 3.11+ | Тем, кто будет менять код или загружать данные сам |
| [В. HTML-файл](#вариант-в--один-html-файл) | Только браузер | Тем, кому нужно просто посмотреть цифры |

Во всех вариантах **данные остаются на вашем компьютере**. Ничего никуда не
отправляется, интернет нужен только на этапе установки.

---

## Вариант А — Docker

### Шаг 1. Установить Docker Desktop

Скачать с <https://www.docker.com/products/docker-desktop/>, установить,
запустить. Дождаться, пока значок кита перестанет мигать.

Проверка — в терминале (PowerShell на Windows, Terminal на macOS):

```bash
docker --version
```

Должна появиться строка вида `Docker version 27.x.x`.

### Шаг 2. Получить проект

```bash
git clone <адрес репозитория>
cd ReportsDB
```

Если git не установлен — скачайте архив кнопкой «Code → Download ZIP» на
странице репозитория и распакуйте.

### Шаг 3. Положить файлы с данными

Скопируйте свои Excel-файлы в папку `data/raw/` внутри проекта.
Можно и пропустить этот шаг — файлы получится загрузить прямо из интерфейса.

### Шаг 4. Запустить

```bash
docker compose -f docker/docker-compose.yml up --build
```

Первый запуск займёт 2–5 минут: скачивается образ Python и ставятся
библиотеки. Последующие — несколько секунд.

Когда в терминале появится `You can now view your Streamlit app`, откройте в
браузере <http://localhost:8501>.

### Шаг 5. Загрузить данные

В меню слева — **Загрузка данных**. Дальше по шагам на странице:
выбрать файл с отчётами, при необходимости файлы с размерами и статистикой,
нажать **Загрузить**. Подробнее — [ниже](#как-загружать-данные).

### Остановить

`Ctrl+C` в терминале. Либо в другом окне:

```bash
docker compose -f docker/docker-compose.yml down
```

Данные при остановке не теряются: папка `data/` подключена к контейнеру
напрямую и живёт на вашем диске.

### Запустить повторно

```bash
docker compose -f docker/docker-compose.yml up
```

Без `--build` — образ уже собран.

### Передать образ коллеге

Коллеге не нужен ни репозиторий, ни ваши Excel-файлы: **собранная база лежит
внутри образа**. Нужен только Docker.

**Шаг 1. Соберите базу у себя** и убедитесь, что цифры верные — в образ попадёт
именно то, что вы видите сейчас в приложении.

**Шаг 2. Соберите образ:**

```bat
docker compose -f docker\docker-compose.yml build
```

**Шаг 3. Сохраните образ в файл:**

```bat
docker save reportsdb:latest -o reportsdb-image.tar
```

Файл получится большой — около 1 ГБ (внутри Python и библиотеки). Сожмите, если
передаёте по почте или через файлообменник:

```bat
docker save reportsdb:latest | gzip > reportsdb-image.tar.gz
```

В PowerShell конвейера с `gzip` нет — сохраните `.tar` и сожмите архиватором,
получится примерно втрое меньше.

**Шаг 4. Передайте файл** — сетевая папка, флешка, файлообменник компании.

> ⚠️ **Внутри образа рабочие данные.** Там и собранная база, и исходные
> Excel-файлы из `data/`. Передавайте образ так же осторожно, как саму выгрузку,
> и **не публикуйте его в Docker Hub и других открытых реестрах.**

**Шаг 5. Коллега загружает образ и запускает:**

```bat
docker load -i reportsdb-image.tar
docker run -d -p 8501:8501 --name reportsdb reportsdb:latest
```

Для сжатого файла: `docker load -i reportsdb-image.tar.gz` — `docker load`
распознаёт gzip сам.

Дальше открыть <http://localhost:8501>. Остановить — `docker stop reportsdb`,
запустить снова — `docker start reportsdb`, удалить —
`docker rm -f reportsdb`.

### Что коллега может и чего не может

**Может:** смотреть всю аналитику, фильтровать, выгружать CSV, выполнять
произвольный SQL, собрать себе HTML-файл.

**Не может (без дополнительных действий):** сохранить свои данные. Если он
загрузит файлы через интерфейс, они попадут внутрь контейнера и исчезнут при
`docker rm`. Чтобы данные жили на его диске, пусть подключит папку:

```bat
docker run -d -p 8501:8501 -v C:\reportsdb-data:/app/data --name reportsdb reportsdb:latest
```

Но тогда подключённая папка **полностью заменяет** данные из образа: если она
пустая, приложение встретит его пустой базой. Это нужно только тем, кто будет
грузить свои файлы; читателю достаточно команды без `-v`.

### Как обновить у коллеги

Образ — снимок данных на момент сборки. Чтобы обновить, соберите заново и
повторите шаги 2–5; коллега перед `docker load` удаляет старый контейнер:

```bat
docker rm -f reportsdb
```

Если у коллеги есть доступ к репозиторию и Docker, проще другое: он делает
`git clone`, вы передаёте только файлы данных, и он собирает образ сам командой
из шага 4 варианта А. Тогда пересылать гигабайт каждый раз не нужно.

## Вариант Б — Python

### Шаг 1. Установить Python 3.11 или новее

<https://www.python.org/downloads/> — при установке на Windows обязательно
поставьте галочку **«Add Python to PATH»**.

Проверка:

```bash
python --version     # Windows
python3 --version    # macOS / Linux
```

### Шаг 2. Получить проект

```bash
git clone <адрес репозитория>
cd ReportsDB
```

### Шаг 3. Запустить одной командой

**Windows:**

```bat
scripts\run.bat
```

**macOS / Linux:**

```bash
./scripts/run.sh
```

Скрипт сам создаст изолированное окружение, поставит библиотеки и откроет
приложение на <http://localhost:8501>. Если базы ещё нет, он соберёт её на
демонстрационных данных, чтобы было что посмотреть.

### Если скрипт не подошёл — вручную

```bash
python -m venv .venv

# Windows:
.venv\Scripts\activate
# macOS / Linux:
source .venv/bin/activate

pip install -e .
streamlit run app/Home.py
```

### Шаг 4. Загрузить данные

Либо через интерфейс (страница **Загрузка данных**), либо командой:

```bat
scripts\rdb.bat build data\raw\ваш_файл.xlsx
```

macOS/Linux — `scripts/rdb.sh build data/raw/ваш_файл.xlsx`.

### Остановить

`Ctrl+C` в терминале.

## Вариант В — один HTML-файл

Для коллег, которым нужно только посмотреть. Устанавливать нечего.

### Как получить файл

Тот, у кого проект уже работает (вариант А или Б), делает одно из двух:

- в меню **Инструменты → Файл для коллег** нажимает **Собрать HTML-файл**, затем
  **Скачать**;
- или выполняет в терминале:

  ```bat
  scripts\rdb.bat export-html
  ```

  (macOS/Linux — `scripts/rdb.sh export-html`.)
  Файл появится в `dist/reportsdb.html`.

### Как пользоваться

Отправить файл коллеге любым способом — почтой, мессенджером, на флешке.
Получатель сохраняет его на диск и открывает двойным кликом.

Внутри — то же, что в приложении: вкладки собраны по тем же разделам меню
(Обзор, вся «Аналитика РЦ» №1–№5, весь раздел «Отчёты» — карточка, объём и
стоимость, кандидаты на вывод, похожие отчёты, ABC-анализ, — и справочник
объектов). Те же показатели, те же колонки, тот же разбор строки по щелчку,
общий выбор РЦ на весь файл. Списки идут целиком, ничего не обрезается.
Поиск, сортировка и выгрузка выборки в CSV работают без интернета, есть
светлая и тёмная тема.

Не переносятся только загрузка данных и произвольный SQL — это инструменты
владельца базы.

Файл — **снимок данных на момент сборки**. Чтобы обновить, соберите заново и
разошлите новую версию.

## Как загружать данные

Страница **Загрузка данных** в меню слева. Командная строка не нужна.

### Шаг 1. Файлы

Два равнозначных способа:

- скопировать файлы в папку `data/raw/` внутри проекта — они появятся в
  списках на странице;
- перетащить файлы в поле загрузки на странице — они сохранятся в ту же папку.

Форматы: `.xlsx`, `.xls`, `.xlsm`, `.csv`, `.tsv`.

### Шаг 2. Указать, что чем является

| Поле | Что выбрать |
| --- | --- |
| **Отчёты** | Обязательно. Строка на отчёт: №, ТС, завод, каталог тремя уровнями, наименование, признак view, таблицы-источники, средняя длительность и число обращений |
| **Размеры таблиц** | Если есть. Выгрузка сегментов БД: `ТС`, `Завод`, `OWNER`, `SEGMENT_NAME`, `SEGMENT_TYPE`, `SIZE_MB`, `PERCENT_OF_TOTAL`, `Глубина хранения`. `ТС` и `Завод` необязательны, но без них размер считается общим для всех заводов, хотя на каждом заводе он свой |
| **Частота использования** | Обычно не нужен: число обращений и длительность уже есть в основном файле. Отдельный файл нужен, только если статистика ведётся отдельно — тогда его значения перекроют основной файл |

Файла размеров может не быть — загрузите его позже, когда появится. Аналитика
работает и без него, просто столбцы с объёмами будут пустыми.

Если в книге несколько листов, появится выбор листа.

### Несколько файлов — по одному на завод

**В каждое поле можно выбрать сразу несколько файлов.** Так и надо делать,
когда выгрузка приходит по файлу на завод: отметьте все файлы отчётов в первом
поле, все файлы размеров во втором и нажмите «Загрузить» один раз. Файлы
склеятся и загрузятся за один проход.

Завод у каждой строки берётся из колонок **ТС** и **Завод** внутри файла, а не
из того, какой это файл. Поэтому порядок выбора не важен, а один и тот же файл
случайно выбранный дважды ничего не испортит.

> **Если в файлах размеров нет колонок ТС и Завод**, а файлов несколько —
> страница покажет красное предупреждение. Загрузка при этом не упадёт, но
> размеры разных заводов сложатся в один, и цифры будут завышены. Добавьте
> колонки в выгрузку либо загружайте файлы размеров по одному.

База каждый раз пересобирается целиком: одна загрузка = вся база из
перечисленных файлов. Догрузить один завод к уже собранной базе нельзя — это
сделано намеренно, чтобы не гадать, какие данные в базе свежие, а какие нет.

> **Если числа в таблице №1 не сходятся с вашим файлом** — таблиц больше, чем
> вы насчитали, или объём не тот — запустите сверку:
>
> ```
> scripts\rdb.bat diagnose
> ```
>
> (macOS/Linux — `scripts/rdb.sh diagnose`.) Именно через `rdb`, а не
> `python -m reportsdb`: приложение живёт в виртуальном окружении проекта, и
> обычная консоль пакета не видит — отвечает «No module named reportsdb».
>
> Она читает файл размеров ровно так же, как загрузчик, и показывает, на каком
> шаге числа расходятся: какие колонки распознаны, сколько строк какого типа
> сегмента учтено, сколько получается уникальных таблиц и совпадает ли это с
> базой. Имена таблиц не печатаются; чтобы увидеть их локально — ключ
> `--show-names`.
>
> Две самые частые причины:
>
> 1. **Колонка типа сегмента не распознана.** Тогда индексы и LOB-сегменты
>    считаются таблицами: и число таблиц, и объём завышены. Впишите фактическое
>    имя колонки в `config/mapping.yml` → `table_sizes.columns.segment_type`.
> 2. **Считали по `SEGMENT_NAME` без схемы.** Одно имя таблицы встречается в
>    нескольких схемах, и это разные таблицы — счёт по `OWNER.SEGMENT_NAME`
>    больше. Сверка показывает обе цифры.

### Шаг 3. Проверить колонки

На каждый выбранный файл — своя вкладка. В таблице видно, какая колонка файла
соответствует какому ожидаемому полю:

- ✅ — колонка найдена;
- • — не найдена. Под таблицами раскрывается список «что будет недоступно» с
  объяснением по каждому пункту.

Загрузку блокируют только две вещи: отсутствие наименования отчёта и
отсутствие `SIZE_MB` в файле размеров. Всё остальное — предупреждения.

Отдельно стоит обратить внимание на `SEGMENT_TYPE`: без него в размер таблиц
попадут индексные и LOB-сегменты и завысят его.

**Если наименование отчёта не нашлось:** откройте `config/mapping.yml`, найдите
`reports: → columns: → report_name:` и допишите заголовок вашего файла новой
строкой списка. Сохраните и обновите страницу в браузере.

Регистр, лишние пробелы и «ё» вместо «е» роли не играют — сопоставление их
не различает.

### Колонки для пяти основных таблиц

Пять представлений в разрезе РЦ заполняются из этих колонок:

| Таблица | Нужна колонка |
| --- | --- |
| №1 Объект и размер | `SIZE_MB` в файле размеров |
| №2 Отчёт → таблицы | `Таблицы источники данных`; плюс `View`, `Mat.view`, `Временные таблицы` — чтобы эти объекты **не** попали в №2 |
| №3 Отчёт → функции | `Функции/процедуры` в файле отчётов |
| №4 Отчёт → обращения | `Кол-во обращений` в файле отчётов |
| №5 Отчёт → глубина | `Глубина хранения` в файле размеров |

Если отдельных колонок `View`, `Mat.view` и `Временные таблицы` в файле нет,
тип объекта определяется маской имени из `config/mapping.yml` — по умолчанию
включена одна: префикс `v_` (и `vw_`) означает представление. К объектам,
найденным в файле размеров, маска не применяется: у них есть сегменты, значит
они физически хранятся, и это таблицы. Откуда взят тип каждого объекта, видно
в справочнике **Таблицы** — колонка «Тип определён».

Каждой недостающей колонки страница загрузки касается отдельно и пишет, какая
именно таблица останется пустой.

### Шаг 4. Нажать «Загрузить»

База пересобирается с нуля за секунды. После этого страница покажет:
сколько строк прочитано, сколько отчётов загружено, сколько нашлось уникальных
таблиц и связей.

Предупреждения, если что-то не сошлось:

| Сообщение | Что значит |
| --- | --- |
| Отброшено строк | В строке пустое наименование отчёта. Список — в раскрывающемся блоке ниже |
| Ссылок на таблицы без схемы | В списке источников имя без точки, например `TempTable`. Схема записана как `(unknown)` |
| Размеры не сопоставились | В файле размеров есть таблицы, которых нет ни в одном отчёте. Обычно это нормально |
| Пропущено сегментов не-табличных типов | Индексные и LOB-сегменты. Так и задумано: привязать их к таблице по выгрузке нельзя, в объём таблицы они не входят |
| Статистика не сопоставилась | Наименования отчётов в файле статистики не совпали с каталогом. Проверьте написание |

Прежняя база сохраняется рядом как `reports.duckdb.bak` — если загрузили не
тот файл, можно вернуть, переименовав обратно.

### Как стереть все данные

На той же странице, сразу под текущим состоянием, есть свёрнутый блок
**🗑️ Очистить базу**. Он стирает всё загруженное: отчёты, таблицы, размеры и
статистику.

1. Раскройте блок — он покажет, что именно будет удалено и сколько это
   мегабайт.
2. Поставьте флажок **«Да, стереть все данные из базы»** — без него кнопка не
   нажимается.
3. Нажмите **Очистить базу**.

Что происходит:

- остаётся **пустая база нужной структуры**, а не удалённый файл: страницы
  аналитики продолжают открываться и честно показывают нули;
- **резервная копия `reports.duckdb.bak` удаляется вместе с базой.** Очистку
  просят, когда рабочих данных на машине быть не должно, а копия рядом с
  пустой базой сохранила бы ровно то, что просили стереть. Нужна страховка —
  поставьте флажок «Оставить резервную копию»;
- **исходные файлы в `data/raw/` не трогаются.** Это ваши файлы, а не
  содержимое базы. Если данные не должны оставаться на машине, удалите их
  отдельно, обычным способом.

**Отменить очистку нельзя.** Чтобы вернуть данные, загрузите файлы заново.

То же самое из командной строки:

```bat
scripts\rdb.bat clear
```

(macOS/Linux — `scripts/rdb.sh clear`.) Команда спросит подтверждение; ключ
`--yes` его пропускает, `--keep-backup` сохраняет `.bak`.

## Поиск сразу по нескольким таблицам

Поле поиска на любой странице принимает **несколько значений сразу**. Три
равнозначных способа:

- через запятую: `dbo.orders, fin.invoice, sales.audit`;
- через точку с запятой: `dbo.orders;fin.invoice`;
- **столбцом из Excel** — выделите колонку с именами таблиц, скопируйте и
  вставьте в поле как есть.

Строка попадёт в результат, если подходит **хотя бы под одно** значение. Это
именно разбор списка «покажи вот эти таблицы»; искать пересечение
(«и та, и другая одновременно») смысла нет — у разных таблиц оно всегда пусто.

Под таблицей видно, сколько значений в запросе и **по каким из них ничего не
нашлось** — при вставке списка это главное: сразу понятно, чего в базе нет.

Пробел разделителем **не** считается: имена отчётов состоят из нескольких слов,
и «Продажи за месяц» иначе распалось бы на три обрывка.

### Часть имени или точное совпадение

По умолчанию ищется **часть имени**: `invoice` найдёт и `fin.invoice`, и
`sales.invoice_stg`. Так удобно, когда помнишь фрагмент.

Для списка готовых имён этого мало: `itm.log` притащит заодно `dbo.catalog` и
`wh1.errlog` — «log» есть и в них. Поставьте флажок **«Точное совпадение»** под
полем поиска: тогда имена сравниваются целиком.

Имя **без схемы тоже считается совпадением**: `TRIP_LOG` найдёт `sdd.trip_log`.
Это нужно потому, что в выгрузках половина имён приходит со схемой, а половина
без, и разбирать список по частям не приходится.

### Все отчёты по списку таблиц сразу

На странице **№2 → вкладка «По таблицам»**, как только поиск что-то отобрал,
над списком раскрывается блок **«Все отчёты по найденным таблицам»**. В нём
строки «таблица + отчёт» по **всем** найденным таблицам разом — не нужно
щёлкать по каждой строке и выписывать отчёты вручную. Рядом кнопка выгрузки
в CSV.

Один отчёт встречается в этом списке столько раз, сколько ваших таблиц он
использует, — это связи, а не список отчётов.

Кнопка **«Выгрузить в Excel: два листа»** отдаёт `.xlsx` с двумя листами:

| Лист | Строка | Колонки |
| --- | --- | --- |
| **Отчёты** | отчёт | ТС, завод, каталог, сколько ваших таблиц он держит, сами таблицы через `;`, суммарный объём |
| **Таблицы и отчёты** | пара «таблица + отчёт» | то же, что видно на экране |

Шапка закреплена, ширина колонок подогнана — файл открывается и читается без
правки. Числа остаются числами: по ним сразу работают формулы и сортировка.

## Частые вопросы

**«База собрана прежней версией программы».** Появляется после `git pull`,
если код обновился, а база осталась прежней. Откройте **Загрузка данных**,
выберите файлы и нажмите **Загрузить** — это всё, что нужно. Исходные файлы в
`data/raw/` не тронуты, прежняя база сохранится как `reports.duckdb.bak`.

**Порт 8501 занят.** Запустите на другом порту:
`streamlit run app/Home.py --server.port 8502`, для Docker поправьте `ports`
в `docker/docker-compose.yml`.

**Кириллица в CSV открывается кракозябрами.** Выгрузки содержат BOM и
открываются в Excel корректно. Если всё же нет — при открытии выберите
кодировку UTF-8.

**Данные попадут в GitHub?** Нет. Папки `data/` и `dist/` закрыты
`.gitignore`, в репозиторий уходит только код.

**Как обновить данные.** Положите новый файл и нажмите «Загрузить» ещё раз.
База каждый раз собирается заново — накопления и дублей не будет.

**Ничего не открывается после `docker compose up`.** Проверьте, что Docker
Desktop запущен, и дождитесь строки `You can now view your Streamlit app` —
на первом запуске это занимает несколько минут.
