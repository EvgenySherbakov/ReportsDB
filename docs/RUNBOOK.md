# Инструкция по запуску

Три способа. Выберите один — они не зависят друг от друга.

| Способ | Что нужно | Кому подойдёт |
| --- | --- | --- |
| [А. Docker](#вариант-а--docker) | Docker Desktop | Большинству: ставится один раз, дальше одна команда |
| [Б. Python](#вариант-б--python) | Python 3.11+ | Тем, кто будет менять код или загружать данные сам |
| [В. HTML-файл](#вариант-в--один-html-файл) | Только браузер | Тем, кому нужно просто посмотреть цифры |

Во всех вариантах **данные остаются на вашем компьютере**. Ничего никуда не
отправляется, интернет нужен только на этапе установки.

---

## Вариант А — Docker

### Шаг 1. Установить Docker Desktop

Скачать с <https://www.docker.com/products/docker-desktop/>, установить,
запустить. Дождаться, пока значок кита перестанет мигать.

Проверка — в терминале (PowerShell на Windows, Terminal на macOS):

```bash
docker --version
```

Должна появиться строка вида `Docker version 27.x.x`.

### Шаг 2. Получить проект

```bash
git clone <адрес репозитория>
cd ReportsDB
```

Если git не установлен — скачайте архив кнопкой «Code → Download ZIP» на
странице репозитория и распакуйте.

### Шаг 3. Положить файлы с данными

Скопируйте свои Excel-файлы в папку `data/raw/` внутри проекта.
Можно и пропустить этот шаг — файлы получится загрузить прямо из интерфейса.

### Шаг 4. Запустить

```bash
docker compose -f docker/docker-compose.yml up --build
```

Первый запуск займёт 2–5 минут: скачивается образ Python и ставятся
библиотеки. Последующие — несколько секунд.

Когда в терминале появится `You can now view your Streamlit app`, откройте в
браузере <http://localhost:8501>.

### Шаг 5. Загрузить данные

В меню слева — **Загрузка данных**. Дальше по шагам на странице:
выбрать файл с отчётами, при необходимости файлы с размерами и статистикой,
нажать **Загрузить**. Подробнее — [ниже](#как-загружать-данные).

### Остановить

`Ctrl+C` в терминале. Либо в другом окне:

```bash
docker compose -f docker/docker-compose.yml down
```

Данные при остановке не теряются: папка `data/` подключена к контейнеру
напрямую и живёт на вашем диске.

### Запустить повторно

```bash
docker compose -f docker/docker-compose.yml up
```

Без `--build` — образ уже собран.

## Вариант Б — Python

### Шаг 1. Установить Python 3.11 или новее

<https://www.python.org/downloads/> — при установке на Windows обязательно
поставьте галочку **«Add Python to PATH»**.

Проверка:

```bash
python --version     # Windows
python3 --version    # macOS / Linux
```

### Шаг 2. Получить проект

```bash
git clone <адрес репозитория>
cd ReportsDB
```

### Шаг 3. Запустить одной командой

**Windows:**

```bat
scripts\run.bat
```

**macOS / Linux:**

```bash
./scripts/run.sh
```

Скрипт сам создаст изолированное окружение, поставит библиотеки и откроет
приложение на <http://localhost:8501>. Если базы ещё нет, он соберёт её на
демонстрационных данных, чтобы было что посмотреть.

### Если скрипт не подошёл — вручную

```bash
python -m venv .venv

# Windows:
.venv\Scripts\activate
# macOS / Linux:
source .venv/bin/activate

pip install -e .
streamlit run app/Home.py
```

### Шаг 4. Загрузить данные

Либо через интерфейс (страница **Загрузка данных**), либо командой:

```bash
python -m reportsdb build data/raw/ваш_файл.xlsx
```

### Остановить

`Ctrl+C` в терминале.

## Вариант В — один HTML-файл

Для коллег, которым нужно только посмотреть. Устанавливать нечего.

### Как получить файл

Тот, у кого проект уже работает (вариант А или Б), делает одно из двух:

- на странице **Загрузка данных** внизу нажимает **Собрать HTML-файл**, затем
  **Скачать**;
- или выполняет в терминале:

  ```bash
  python -m reportsdb export-html
  ```

  Файл появится в `dist/reportsdb.html`.

### Как пользоваться

Отправить файл коллеге любым способом — почтой, мессенджером, на флешке.
Получатель сохраняет его на диск и открывает двойным кликом.

Внутри: показатели, отчёты с сортировкой и поиском, критичность таблиц,
кандидаты на вывод, выгрузка выборки в CSV. Работает без интернета,
поддерживает светлую и тёмную тему.

Файл — **снимок данных на момент сборки**. Чтобы обновить, соберите заново и
разошлите новую версию.

## Как загружать данные

Страница **Загрузка данных** в меню слева. Командная строка не нужна.

### Шаг 1. Файлы

Два равнозначных способа:

- скопировать файлы в папку `data/raw/` внутри проекта — они появятся в
  списках на странице;
- перетащить файлы в поле загрузки на странице — они сохранятся в ту же папку.

Форматы: `.xlsx`, `.xls`, `.xlsm`, `.csv`, `.tsv`.

### Шаг 2. Указать, что чем является

| Поле | Что выбрать |
| --- | --- |
| **Отчёты** | Обязательно. Строка на отчёт: №, ТС, завод, каталог тремя уровнями, наименование, признак view, таблицы-источники, средняя длительность и число обращений |
| **Размеры таблиц** | Если есть. Выгрузка сегментов БД: `OWNER`, `SEGMENT_NAME`, `SEGMENT_TYPE`, `SIZE_MB`, `PERCENT_OF_TOTAL`, `Глубина хранения` |
| **Частота использования** | Обычно не нужен: число обращений и длительность уже есть в основном файле. Отдельный файл нужен, только если статистика ведётся отдельно — тогда его значения перекроют основной файл |

Файла размеров может не быть — загрузите его позже, когда появится. Аналитика
работает и без него, просто столбцы с объёмами будут пустыми.

Если в книге несколько листов, появится выбор листа.

### Шаг 3. Проверить колонки

На каждый выбранный файл — своя вкладка. В таблице видно, какая колонка файла
соответствует какому ожидаемому полю:

- ✅ — колонка найдена;
- • — не найдена. Под таблицами раскрывается список «что будет недоступно» с
  объяснением по каждому пункту.

Загрузку блокируют только две вещи: отсутствие наименования отчёта и
отсутствие `SIZE_MB` в файле размеров. Всё остальное — предупреждения.

Отдельно стоит обратить внимание на `SEGMENT_TYPE`: без него в размер таблиц
попадут индексные и LOB-сегменты и завысят его.

**Если наименование отчёта не нашлось:** откройте `config/mapping.yml`, найдите
`reports: → columns: → report_name:` и допишите заголовок вашего файла новой
строкой списка. Сохраните и обновите страницу в браузере.

Регистр, лишние пробелы и «ё» вместо «е» роли не играют — сопоставление их
не различает.

### Колонки для пяти основных таблиц

Пять представлений в разрезе РЦ заполняются из этих колонок:

| Таблица | Нужна колонка |
| --- | --- |
| №1 Объект и размер | `SIZE_MB` в файле размеров |
| №2 Отчёт → таблицы | `Таблицы источники данных`; плюс `View`, `Mat.view`, `Временные таблицы` — чтобы эти объекты **не** попали в №2 |
| №3 Отчёт → функции | `Функции/процедуры` в файле отчётов |
| №4 Отчёт → обращения | `Кол-во обращений` в файле отчётов |
| №5 Отчёт → глубина | `Глубина хранения` в файле размеров |

Каждой недостающей колонки страница загрузки касается отдельно и пишет, какая
именно таблица останется пустой.

### Шаг 4. Нажать «Загрузить»

База пересобирается с нуля за секунды. После этого страница покажет:
сколько строк прочитано, сколько отчётов загружено, сколько нашлось уникальных
таблиц и связей.

Предупреждения, если что-то не сошлось:

| Сообщение | Что значит |
| --- | --- |
| Отброшено строк | В строке пустое наименование отчёта. Список — в раскрывающемся блоке ниже |
| Ссылок на таблицы без схемы | В списке источников имя без точки, например `TempTable`. Схема записана как `(unknown)` |
| Размеры не сопоставились | В файле размеров есть таблицы, которых нет ни в одном отчёте. Обычно это нормально |
| Пропущено сегментов не-табличных типов | Индексные и LOB-сегменты. Так и задумано: привязать их к таблице по выгрузке нельзя, в объём таблицы они не входят |
| Статистика не сопоставилась | Наименования отчётов в файле статистики не совпали с каталогом. Проверьте написание |

Прежняя база сохраняется рядом как `reports.duckdb.bak` — если загрузили не
тот файл, можно вернуть, переименовав обратно.

## Частые вопросы

**«База собрана прежней версией программы».** Появляется после `git pull`,
если код обновился, а база осталась прежней. Откройте **Загрузка данных**,
выберите файлы и нажмите **Загрузить** — это всё, что нужно. Исходные файлы в
`data/raw/` не тронуты, прежняя база сохранится как `reports.duckdb.bak`.

**Порт 8501 занят.** Запустите на другом порту:
`streamlit run app/Home.py --server.port 8502`, для Docker поправьте `ports`
в `docker/docker-compose.yml`.

**Кириллица в CSV открывается кракозябрами.** Выгрузки содержат BOM и
открываются в Excel корректно. Если всё же нет — при открытии выберите
кодировку UTF-8.

**Данные попадут в GitHub?** Нет. Папки `data/` и `dist/` закрыты
`.gitignore`, в репозиторий уходит только код.

**Как обновить данные.** Положите новый файл и нажмите «Загрузить» ещё раз.
База каждый раз собирается заново — накопления и дублей не будет.

**Ничего не открывается после `docker compose up`.** Проверьте, что Docker
Desktop запущен, и дождитесь строки `You can now view your Streamlit app` —
на первом запуске это занимает несколько минут.
